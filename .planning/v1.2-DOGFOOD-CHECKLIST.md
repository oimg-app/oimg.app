## Phase 13 — Diagnostics + Clear Queue (3 checks)

- [ ] **13-D1: Clipboard round-trip into real bug-report editor**
  - **Steps:** Open Settings popover → Diagnostics tab → click "Copy diagnostics". Paste into a real bug-report editor (GitHub issue textarea, Notion, Linear).
  - **Expected:** JSON is human-readable, parseable, and contains live values for `versions.svgo`, all `versions.jsquash.*`, `versions.ssim`, `versions.butteraugli.buildHash`, plus `caps.simd`, `caps.threads`, `caps.crossOriginIsolated`, `caps.hardwareConcurrency`.
  - **Why human:** clipboard round-trip crosses application boundary.

- [ ] **13-D2: StatusBar version badges at WCAG-AA contrast (dark + light)**
  - **Steps:** Toggle theme (StatusBar → theme switch). Read `svgo`, `jSquash*`, `ssim`, `butteraugli` badges under both dark and light backgrounds.
  - **Expected:** Text remains legible; contrast ratio ≥ 4.5:1 for normal text (spot-check with browser DevTools accessibility inspector if unsure).
  - **Why human:** visual judgment; VALIDATION.md §Manual-Only row 3.

- [ ] **13-D3: Capability detection on a real low-end device**
  - **Steps:** Load the deployed app on an older iPhone or low-end Android. Open Settings → Diagnostics tab.
  - **Expected:** `caps.simd` and `caps.threads` reflect actual hardware support (may be `false` on older iOS/Safari; `true` on modern Chrome).
  - **Why human:** CI runners don't represent low-end mobile silicon.

## Phase 14 — Installable PWA (6 checks)

- [ ] **14-D1: Lighthouse PWA audit ≥ 80**
  - **Steps:** `npm run build && npm run preview`. Open Chrome DevTools → Lighthouse → PWA category → Analyze page load.
  - **Expected:** PWA score ≥ 80. Precache list does NOT include AVIF wasm (~3.4 MB). Manifest + service worker report as installable.
  - **Why human:** Lighthouse runs live in Chrome DevTools; no headless equivalent covers all its checks.

- [ ] **14-D2: Cloudflare Pages `_headers` post-deploy curl**
  - **Steps:** After deploying to Cloudflare Pages, run:
    ```
    curl -I https://oimg.app/sw.js
    curl -I https://oimg.app/manifest.webmanifest
    curl -I https://oimg.app/
    ```
  - **Expected:** `/sw.js` returns `cache-control: no-cache`. `/manifest.webmanifest` returns `cache-control: public, max-age=86400`. `/` returns `cross-origin-opener-policy: same-origin` + `cross-origin-embedder-policy: require-corp` (or `credentialless`).
  - **Why human:** headers only exist on the live edge, not in `dist/`.

- [ ] **14-D3: `crossOriginIsolated` survives SW takeover**
  - **Steps:** Load deployed app in Chrome. Wait for SW registration. Open DevTools → Application → Service Workers → confirm "controls this page". Open Console → run `self.crossOriginIsolated`. Then optimize a PNG file with OxiPNG (multi-threaded codec).
  - **Expected:** `crossOriginIsolated === true` even after SW takes over. OxiPNG optimize succeeds (SharedArrayBuffer works).
  - **Why human:** requires deployed environment with real SW lifecycle.

- [ ] **14-D4: Real Chrome `beforeinstallprompt` flow**
  - **Steps:** Load deployed app in fresh Chrome profile. Wait for Install button to surface in StatusBar. Click it → confirm browser install dialog. Complete install → confirm Install button disappears.
  - **Expected:** Button appears, prompt fires, `appinstalled` event hides button. Reload → button stays hidden (already installed).
  - **Why human:** Chrome only fires `beforeinstallprompt` after real heuristics (engagement time, HTTPS, manifest served); can't be scripted.

- [ ] **14-D5: Second-visit offline reload**
  - **Steps:** Load deployed app. Wait for SW to precache. Open DevTools → Network → Offline. Reload page.
  - **Expected:** App shell loads (index.html + JS + CSS + logo). "Offline-ready" indicator green in StatusBar.
  - **Why human:** requires deployed environment; local `vite preview` is close but not identical.

- [ ] **14-D6:** ⚙️ *Currently automatable — see "Automatable Follow-ups" ⚙️-1 (playwright.pwa.config.ts under vite preview).*

## Phase 15 — From URL or paste (3 checks)

- [ ] **15-D1: Real third-party CORS-blocked URL surfaces recovery toast**
  - **Steps:** Copy a real image URL from a CORS-restrictive server (e.g. a Google Images result, or paste `https://picsum.photos/id/237/200/300` if that domain sets restrictive CORS today). Open Toolbar → "From URL or paste".
  - **Expected:** Toast surfaces: "URL blocked by CORS — download and drop the file, or paste it directly." Then download that file locally, drag-and-drop → ingest succeeds.
  - **Why human:** live third-party CORS behavior varies; `page.route` mocks in CI can't replicate.

- [ ] **15-D2: Safari Cmd+V clipboard image ingest**
  - **Steps:** Open Safari (macOS). Copy an image from Safari Photos, a screenshot, or another Safari tab. Open the deployed app in Safari. Press Cmd+V anywhere outside an input.
  - **Expected:** Ingest fires + "Pasted image imported" toast surfaces. Image appears in FilesPane.
  - **Why human:** Playwright config only runs chromium; Safari's ClipboardEvent + DataTransferItem differs.

- [ ] **15-D3:** ⚙️ *Currently covered automatically by `paste-ingest.spec.ts` Case C, human-verify was a belt-and-suspenders check per 15-VALIDATION.md. Consider clearing from the human-needed list if the spec has been green for a while.*
